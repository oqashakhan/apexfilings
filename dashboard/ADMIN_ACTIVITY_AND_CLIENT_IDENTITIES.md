# Admin activity and client identities

## Implemented

- Recent Activity now displays the newest 10 audited actions, friendly descriptions, category icons, actor/customer/company context, relative time, precise UTC timestamps, status details and related-record links.
- `/admin/activity` provides the complete recorded audit history with server-side search, category/actor/date filters, newest/oldest sorting, counts, pagination, refresh and loading/empty/error states. An upper timestamp and deterministic ID ordering keep ordinary new inserts from shifting an existing result snapshot. Date bounds explicitly use Prisma's UTC timestamp representation, independent of the PostgreSQL session time zone.
- Existing `AuditLog` is the sole event source, enriched through existing user/company/application/document/order/invoice/payment/refund/support/service relations. No notification/status-history copies or synthetic historical events are added. Only allowlisted status/review/sharing metadata is presented; passwords, codes, tokens, note bodies, files and arbitrary audit JSON are excluded.
- Recorded registration, application submissions/updates/reviews, document actions, invoice actions, manual/Stripe payment and refund actions, support replies/assignments, service requests/pricing and account email/password changes have friendly labels. Unknown recorded actions receive a neutral label. Unrecorded events, including any historical application-staff assignments without an audit entry, are not reconstructed. A missing actor is labelled System / unrecorded actor.
- A shared linked client identity displays the actual current database full name, with the unchanged permanent reference underneath. It is used in Clients, Applications, recent applications, Orders, Documents, Payments, refund requests, Invoices (desktop/mobile), Support, Additional Service Requests and activity context. Missing names display Name not provided; missing references are not generated by the UI.
- Client/customer relations are projected directly onto application/order/document/payment/refund rows instead of relying on a separate capped client list. Admin invoice tables use a separate current `clientIdentity` projection; frozen invoice/PDF customer details and financial values are preserved.
- Names and references are searchable. Existing loaded-table searches are retained; client directory, support, service-request and invoice searches also use their existing authorized APIs. Detail-scoped snapshots and exact ticket/request fallbacks allow activity links to load records beyond default list caps.
- Admin APIs/layout remain Owner-only. Clients, Staff and unauthenticated callers cannot use the new Admin activity API. No new Staff access is granted.
